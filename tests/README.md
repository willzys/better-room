# Tests

Run `yarn install`, then `yarn test`. Yarn uses the pinned local Bun runtime. The Bun preload registers teardown; database suites start temporary PostgreSQL and MongoDB servers only when loaded. Only the Prisma suite generates its client, before dynamically importing it. Unit suites neither generate the client nor start databases. The first MongoDB run downloads its binary into `node_modules/.cache/mongodb-binaries`; subsequent runs reuse it. Dependency installation scripts must be enabled for Bun and the platform PostgreSQL package.

Direct `bun test` runs use the same preload and preserve Bun's filters and flags. They require Bun 1.4.2 or newer: Bun 1.3.14 lacks the V8 snapshot API used by the MongoDB driver. An older global runtime stops immediately with a diagnostic; use `yarn test` to select the installed local runtime. On Windows, the harness uses `pg_ctl` to stop PostgreSQL gracefully and waits for termination before removing its temporary directory.

| Command | Scope |
| --- | --- |
| `yarn test` | All domain, security, plugin and database tests |
| `yarn test:unit` | Domain, security and plugin behavior with memory fixtures |
| `yarn test:integration` | SQL, MongoDB and Prisma integration suites |
| `yarn test:load` | The traffic scenarios with 2000 simultaneous callers on every backend; `ROOM_TRAFFIC=10000 yarn test:load` for the full load |
| `yarn test:generate` | Generate the fixture client into `node_modules/.prisma/better-room` |
| `yarn typecheck` | Check source and test types without generating files |
| `yarn lint` / `yarn format:check` | Check source, configuration and all test TypeScript files |

Pass Bun filters directly, for example `yarn test tests/integration/mongo`. For a focused integration run, use that form instead of adding another directory to `test:integration`, whose existing directory argument selects the whole integration suite.

Prepare types explicitly after installation or a Prisma schema change: run `yarn test:generate`, then `yarn typecheck`. The typecheck requires the generated client because it also checks the Prisma suite; it reports a missing client instead of generating one. In CI, prepare with `yarn install --immutable` and `yarn test:generate`, then verify with `yarn typecheck`, `yarn lint`, `yarn format:check`, `yarn build` and `yarn test`.

To use existing services, set `ROOM_POSTGRES_URL` and/or `ROOM_MONGODB_URL`. PostgreSQL credentials need permission to create and drop test databases. MongoDB credentials need equivalent permissions for databases named `better_room_test_*`. The harness never clears the database in either URL: it creates a unique database for each case and drops only that database. Without URLs the runner binds its own servers to loopback, using temporary storage and ports. On root-only Linux environments, supply service URLs or run as an ordinary user; the harness does not create system users.

`integration/contract.ts` registers the invariants shared by Kysely/SQLite, Drizzle/SQLite, Kysely/PostgreSQL, Drizzle/PostgreSQL, Prisma/PostgreSQL and MongoDB. Each subject lives in `integration/contract/<subject>.ts` under the names `src/` uses (`admission`, `capacity`, `codes`, `identity`, `reads`, `rooms`, plus `schema` and `traffic`, and `identity-race` for the races of a subject that need a file of their own), with the shared helpers in `integration/contract/harness.ts`. The adapter seam is tested the same way, in `unit/plugin/stores/<subject>.test.ts` beside `helpers/stores.ts`. Provider files own setup, exact constraint-error shapes and teardown. PostgreSQL schemas use timezone-aware timestamps. The MongoDB contract uses string ids and provisions only the partial unique index on `roomActor.userId`, which the adapter cannot create; every other index comes from the adapter, and `mongo/mongodb.test.ts` asserts each name the schema declares. `id-modes.test.ts` repeats the code, rotation, attempt and listing paths under `serial`, `uuid` and MongoDB's default ObjectId. The Prisma schema is a local fixture that declares the four uniqueness constraints the plugin relies on; its generated client is disposable. The SQL harnesses use Better Auth's canonical migrations.

The membership listing is walked through its real cursor at its real page size on every backend: 450 memberships across both expiry branches, three pages, each membership exactly once. A database that ignores the requested order shows up there as a repeated or missing membership.

`helpers/` owns typed fixtures, parsed HTTP responses, cookies, scoped crypto spies and database lifecycle. Domain fixtures use a fixed instant; expiry tests update deadlines directly instead of waiting. Tests that replace global crypto methods must remain sequential and restore the original method even after assertion failures.

Races are tested by forcing the interleaving, never by hoping for it. `integration/contract/identity-race.ts` and the race contracts in `admission.ts` wrap one adapter method with a spy that runs the competing request at the exact point the race needs it (a user deleted just before a join writes its membership, a membership landing just before an actor is removed, a room locked just before the capacity gate) and then assert that every room counter equals the seats held and that no membership names a missing actor. Firing requests together with `Promise.all` reproduces only the wide races: the parallel test for one actor joining six times at once catches a missing refund, but no parallel run caught the erasure race, so it is pinned by a spy. Each of these tests was checked by removing the rule it guards and watching it fail on every backend that rule protects.

`integration/contract/traffic.ts` runs the same traffic scenarios at two scales. `yarn test` uses 36 callers, enough to contend every gate in seconds. `yarn test:load` defaults to `ROOM_TRAFFIC=2000` and accepts a larger value from the environment, so `ROOM_TRAFFIC=10000 yarn test:load` runs the full load in about six minutes: that many requests in flight at once, split across rooms whose capacities scale with the traffic, then a churn of departures and arrivals, then everyone leaving. After every wave the room counter, the occupied rows and `getRoomOccupancy` must agree exactly. Waves follow one another instead of sleeping, so the run stays deterministic. `bun test --rerun-each` cannot repeat a database suite against the servers the harness starts: the preload stops them when a pass ends, and a server is never restarted from inside a test, so the next pass fails with a message saying so. Repeat the run from the shell, or point `ROOM_POSTGRES_URL` and `ROOM_MONGODB_URL` at servers the harness does not own, which it never stops.

`unit/conventions.test.ts` checks the structure and the naming the rest of the code follows, so a file in the wrong place, a store or endpoint named off-pattern, a POST route missing from the client, or another project convention broken fails `yarn test` with the offending paths. Unit tests mirror `src/`: `unit/core/operations/<subject>/<operation>.test.ts`, `unit/plugin/<folder>/<file>.test.ts`, and `unit/plugin/stores/<subject>.test.ts` for the adapter seam.
